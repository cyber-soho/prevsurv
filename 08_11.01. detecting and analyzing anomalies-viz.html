Proper Use of Monitoring Tools

Welcome to the Collection phase. A monitoring tool used improperly is worse than no tool at all—it provides false confidence and silent blind spots. This section covers the five core tool families and the critical importance of establishing mathematical baselines before chasing anomalies.

Rule of Thumb: Measure normal before you chase abnormal. An anomaly is simply a deviation from the expected.

The Baseline Principle: Time-of-Day Percentiles

Without a baseline, every alert is noise. A traffic spike at 09:00 is expected business operations; the exact same spike at 02:00 is highly suspicious. We use the p95 metric per hour to establish thresholds.

DNS Queries / min per host
Outbound Bytes / min per host
Failed Logins / min per account
New Processes / day per host

Methodical Analysis: The Three Lanes

Every investigation must touch three distinct lanes to build confidence. A single lane provides a hunch; two lanes justify an investigation; three lanes converging confirm an incident. Pivot deliberately and do not chase one lane to exhaustion.

The Five-Step Traffic Loop

Apply these five steps to every pcap. Spend no more than 10 minutes on the first pass.

1. Conversation Map

Who is talking to whom? (Deliverable: Top-10 convo table)

2. Protocol Mix

What is on the wire? (Deliverable: Protocol hierarchy)

3. Throughput Timeline

When do bytes flow? (Deliverable: I/O graph)

4. Endpoint Reputation

Known good or bad? (Deliverable: VT / WHOIS results)

5. Decode Suspect Flow

What was actually said? (Deliverable: Annotated excerpt)

File Analysis: M-A-C-B Model

Analyze NTFS $STANDARD_INFORMATION timestamps. A classic dropper red flag is all four timestamps matching within ~1 second.

Letter Name What changes it
MModifiedFile content changed
AAccessedFile opened for read
CChangedMFT metadata changed (ACL, attribs)
