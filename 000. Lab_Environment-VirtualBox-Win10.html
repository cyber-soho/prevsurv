The 32 GB of memory is generous — the original briefs assume 8–16 GB. On an eight-year-old machine the two things that actually bite are disk and CPU contention (both covered under Old-Dell tuning), and there is exactly one host setting that can quietly wreck performance.

Turn off every competing hypervisor first

Hyper-V, Virtual Machine Platform, Windows Subsystem for Linux 2 (WSL2), Windows Sandbox, and Core Isolation → Memory Integrity each seize the processor's virtualization extensions and force Oracle VirtualBox into slow software emulation. On this class of laptop that is the difference between usable and unusable.

  • Open Turn Windows features on or off and untick Hyper-V, Virtual Machine Platform, Windows Sandbox, and the Windows Subsystem for Linux.
  • Settings → Privacy & security → Windows Security → Device security → Core isolation → turn Memory integrity off.
  • If VirtualBox still warns about another hypervisor, force it off and reboot:
# Admin PowerShell — only if VirtualBox still complains:
bcdedit /set hypervisorlaunchtype off
# then reboot

Confirm virtualization is enabled, then install the host tools

Reboot into BIOS/UEFI and enable Intel VT-x or AMD-V. Verify it took:

systeminfo | findstr /i "Hyper-V Requirements"
# or: Task Manager -> Performance -> CPU -> "Virtualization: Enabled"

Then install VirtualBox plus the matching Extension Pack (same version number), and GNS3 — the Graphical Network Simulator-3. Both are listed under Host-side tools.

Why Debian 12 and not 13 for the sensor? Wazuh 4.7’s officially-supported matrix lists Debian 10/11/12. The lighter hosts can run Debian 13 — see The three swaps.

Debian sensor — the box that does the heavy lifting

Wireshark + tshark · the Net-SNMP suite + snmp-mibs-downloader · Wazuh 4.7 all-in-one (server + indexer/OpenSearch + dashboard) · Splunk Free 9.x · Python 3 with PyYAML and your helper scripts · PowerShell (pwsh) for the Lab 2 .ps1 scripts · Graphviz (dot) for the three-view rendering · pandoc (optional, Lab 5 one-pager).

# Enable contrib + non-free first (needed for snmp-mibs-downloader):
#   deb822 format -> edit /etc/apt/sources.list.d/debian.sources
#     Components: main contrib non-free non-free-firmware
#   classic format -> append 'contrib non-free' to each deb line in /etc/apt/sources.list
sudo apt update
sudo apt install -y wireshark tshark snmp snmp-mibs-downloader \
                    graphviz python3 python3-yaml
# PowerShell: add Microsoft's apt repo per their docs, then:
sudo apt install -y powershell
# Wazuh — bump THIS VM to 8 GB RAM first, or the indexer crashes the install:
curl -sO https://packages.wazuh.com/4.7/wazuh-install.sh
sudo bash ./wazuh-install.sh -a
# If the OS check rejects the Debian version, re-run with:
sudo bash ./wazuh-install.sh -a --ignore-check
# Splunk Free — register + download the .deb from splunk.com, verify its SHA-256, then:
sudo dpkg -i splunk-9.x.x-amd64.deb
sudo /opt/splunk/bin/splunk start --accept-license
sudo /opt/splunk/bin/splunk enable boot-start
# After the one Wazuh -> Splunk forwarding exercise, reclaim CPU/RAM:
sudo /opt/splunk/bin/splunk stop

pfSense in place of OPNsense

Lab 3 already blesses this — same FreeBSD firewall, same job, only two menus differ:

  • SNMP: Services → SNMP — community string labdemo, location, contact (same fields as OPNsense).
  • Remote syslog: Status → System Logs → Settings → Remote Logging, pointed at 10.10.10.30:514 over UDP (OPNsense put this under System → Settings → Logging/Targets).

Students screenshot pfSense’s own paths. Use the free Community Edition (CE), not pfSense Plus.

Debian in place of Ubuntu

Nothing in the labs is Ubuntu-locked. Three catches, all on the sensor box:

  1. snmp-mibs-downloader lives in Debian’s contrib/non-free — enable it (see Software per VM) or the Phase-2 Management Information Base (MIB) decode step fails. It’s in multiverse on Ubuntu, hence the difference.
  2. Wazuh 4.7 officially lists Debian 10/11/12, so use Debian 12 for that one VM. Debian 13 (trixie) is newer than the matrix and may trip the installer’s OS check — that’s exactly what --ignore-check is for (the packages are architecture-based, so they install fine underneath).
  3. The Network Interface Card (NIC) is usually enp0s3, not ens33 — your briefs already tell students to confirm with ip link and substitute.
Keep VPCS as VPCS. The Virtual PC Simulator is GNS3’s few-megabyte built-in node, not Ubuntu. Drop a Debian VM in only where a node actually has to run tools; for throwaway ping-test nodes the saved RAM matters on this laptop.

Parrot in place of Kali

Lab 1 already lists it (“lighter Kali alternative”). Parrot Security Edition ships the same Wireshark + Nmap toolset, it’s Debian-based, there’s a prebuilt VirtualBox image, and every Kali step in the build — Phase-5 ping / nmap -sn, SPAN capture, Wireshark — runs identically. It’s also a touch lighter on the old processor.

Net effect: the whole lab is now Debian-family except the firewall (FreeBSD, unavoidable for both options). Students juggle one package manager almost everywhere — one less thing to teach.

Snapshots are your save points and your time machine. The Wazuh install is the one step most likely to bite — snapshot right before it. Tick each as you reach it.

  • 00-fresh-install — every VM, immediately after the OS install + guest additions, before any config (Day 05, Phase 6).
  • 01-networked — every VM, after the host-only network is wired and ping works across the lab (end of Day 05).
  • pre-wazuh — sensor only, after RAM is bumped to 8 GB and before running wazuh-install.sh. The most fragile step — this is your one-click rollback.
  • 02-monitoring-stack — sensor + Windows target, after Wazuh + Splunk are up and the first alert has forwarded (end of Lab 3). Roll back here to start Lab 4.
  • pre-attack — Windows target + sensor, right before the Lab 5 live attack chain — lets you replay the exercise.
Disk reminder: dynamically-allocated disks plus snapshots can double your disk use — budget for it under Old-Dell tuning.

RAM is fine

Peak concurrent use is roughly 17–21 GB (Lab 3 with the full stack plus the topology), well inside 32 GB once you reserve about 8 GB for the Windows host.

Disk is the real ceiling

All VMs coexisting is roughly 250–300 GB, and snapshots can double it. Use dynamically-allocated VDIs, keep at least 300 GB free, or park the VMs on an external USB-3 SSD. One hard rule: put at least the Debian sensor on an SSD — OpenSearch on a spinning disk crawls badly enough to look broken.

CPU is the thing to manage

A quad-core (i5/i7-7x00 desktop or H-series) is comfortable; a dual-core U-series ultrabook chip will struggle with the SIEM stack — check which you have:

wmic cpu get name
  • Give the sensor 2 virtual CPUs (vCPU) and the full 8 GB — Wazuh’s indexer dies on the install with less.
  • Install Splunk, run the one Wazuh → Splunk forwarding exercise, then splunk stop to reclaim CPU/RAM — Wazuh already embeds OpenSearch, so you don’t need both indexers running afterward.
  • Don’t fire up the SIEM, the GNS3 topology, and Parrot in the same minute — sequence the heavy moments.

Nested virtualization — leave it off

The switch / VPCS / pfSense topology here doesn’t need VirtualBox’s Nested VT-x/AMD-V (pfSense runs as its own VM linked into GNS3, not nested), which spares the old processor the tax.
